1. Why Offline Base64 Decoding Broke

Before mid-2024, the Base64 token after /articles/ embedded the publisher URL in plain ASCII inside a protobuf message. Today, most fresh Google News links wrap an opaque encrypted token (commonly beginning with AU_yqL) that can only be resolved server-side via Google's batchexecute RPC.

2. The Working Pure-HTTP 2-Step Pipeline (No Puppeteer/Playwright)

  1. Stream-scan /rss/articles/<token> up to 1 MB: Google now places data-n-a-id, data-n-a-ts, and data-n-a-sg near byte 590,508 of the HTML response. Do not truncate at 250 KB, and use a streaming tail-buffer reader so memory stays under 32 KB.
  2. Batch 5 tokens into one batchexecute POST: Posting Fbv4je / garturlreq in batches of 5 cuts HTTP 429 rate limits by 5x compared to 1-by-1 requests.
  3. Add automatic Bing News RSS fallback: In EU regions (where Google redirects to consent.google.com), https://www.bing.com/news/search?q=...&format=rss&mkt=en-US&setlang=en&cc=US embeds the direct publisher URL inside the ?url= query parameter.
// Extract tokens from /rss/articles/ HTML (~590 KB offset)
const sg = html.match(/data-n-a-sg="([^"]+)"/)?.[1];
const ts = Number(html.match(/data-n-a-ts="(\d+)"/)?.[1]);
const id = html.match(/data-n-a-id="([^"]+)"/)?.[1];

// Batch up to 5 tokens in one POST to https://news.google.com/_/DotsSplashUi/data/batchexecute
const inner = JSON.stringify(['garturlreq', [['X','X',['X','X'],null,null,1,1,'US:en',null,1,null,null,null,null,null,0,1],'X','X',1,[1,1,1],1,1,null,0,0,null,0], id, ts, sg]);
const body = 'f.req=' + encodeURIComponent(JSON.stringify([[['Fbv4je', inner, null, '1']]]));
